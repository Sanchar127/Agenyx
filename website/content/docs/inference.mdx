# Inference Service

Agenyx Inference is a FastAPI service that exposes a single, OpenAI-compatible `/v1/chat/completions` endpoint and routes each request to one of several configured backend providers (Ollama, vLLM, OpenAI, or any OpenAI-compatible server). It provides per-model failover, circuit breakers, concurrency control, and Prometheus/OpenTelemetry observability.

The service is intended to run as an internal microservice behind a service-to-service API key, not to be exposed directly to end users.

## Responsibilities

- **One stable API** — `/v1/chat/completions` regardless of which backend serves the model.
- **Provider failover** — a model can be routed to a prioritized list of providers; if one fails, the next is tried automatically.
- **Circuit breaking** — a provider that keeps failing is temporarily taken out of rotation.
- **Concurrency control** — an in-process admission limiter protects the service and its backends.
- **Observability** — structured JSON logs, Prometheus metrics, and OpenTelemetry traces.

## Endpoints

| Method | Path | Description | Auth |
|--------|------|-------------|------|
| GET | `/health` | Liveness probe | No |
| GET | `/ready` | Readiness probe (at least one provider reachable) | No |
| GET | `/metrics` | Prometheus metrics | No |
| GET | `/v1/models` | List registered models | Yes |
| GET | `/v1/providers` | List registered providers | Yes |
| GET | `/v1/reliability` | Provider reliability / circuit-breaker state | Yes |
| POST | `/v1/chat/completions` | OpenAI-compatible chat completion | Yes (`X-Agenyx-Service-Key`) |

### Chat Completions

**Request**

```http
POST /v1/chat/completions
Content-Type: application/json
X-Agenyx-Service-Key: <INFERENCE_SERVICE_API_KEY>

{
  "model": "qwen2.5:7b",
  "messages": [{"role": "user", "content": "Hello!"}]
}
```

**Response**

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "created": 1700000000,
  "model": "qwen2.5:7b",
  "choices": [
    {
      "index": 0,
      "message": {"role": "assistant", "content": "Hi there!"},
      "finish_reason": "stop"
    }
  ],
  "usage": {...}
}
```

The response includes `X-Agenyx-Provider` and `X-Agenyx-Model` headers indicating which provider and model served the request.

## Provider Failover & Circuit Breaking

Each model is mapped to one or more providers in priority order. On a provider failure, the failover manager tries the next provider in the list.

The **Reliability Manager** tracks per-provider state:

- Consecutive failures and total failures/successes
- Circuit state: `closed` → `open` → `half-open`
- Timestamps for last failure, last success, circuit opened, and circuit half-opened

A provider that exceeds its failure threshold is opened (temporarily removed from rotation) and later probed in a half-open state to test recovery.

Read the current state at `GET /v1/reliability`.

## Concurrency Control

An in-process admission limiter caps the number of concurrent inference requests (`max_concurrency`, default `10`). Requests above the limit receive `429` (`INFERENCE_CONCURRENCY_LIMIT`) until capacity frees.

## Observability

- **Structured JSON logs** — every request and error is logged as JSON.
- **Prometheus metrics** — `GET /metrics` exposes HTTP request counts/durations/errors and inference-specific counters (requests in progress, total, duration).
- **OpenTelemetry tracing** — traces are exported to an OTLP endpoint (default `http://agenyx-otel-collector.monitoring.svc.cluster.local:4317`).

## Configuration

Configuration is loaded from `config/inference.yaml` with environment variables (prefix `INFERENCE_`) overriding YAML values.

### Environment Variables (examples)

| Variable | Purpose |
|----------|---------|
| `INFERENCE_SERVICE_API_KEY` | Required service-to-service API key |
| `INFERENCE_PROVIDER_NAMES` | Comma-separated provider names |
| `INFERENCE_PROVIDER_BACKENDS` | `name=url|type` provider backend mappings |
| `INFERENCE_MODEL_DEFINITIONS` | `model_id=provider_name` model mappings |
| `INFERENCE_OPENAI_API_KEY` | API key for OpenAI-compatible providers |

### Runtime Settings

| Setting | Default | Description |
|---------|---------|-------------|
| `max_retries` | `2` | Max retries per provider request |
| `request_timeout_seconds` | `120.0` | Upstream request timeout |
| `max_connections` | `100` | HTTP client max connections |
| `max_concurrency` | `10` | Concurrent admission limit |
| `max_failover_attempts` | `3` | Max failover attempts per model |
| `max_request_body_bytes` | `1048576` | Max request body size |
| `max_messages` | `100` | Max messages per request |
| `otel_service_name` | `agenyx-inference` | OpenTelemetry service name |

### Limits Enforced

- Request body: `max_request_body_bytes` (default 1 MiB) → `413`
- Message count: `max_messages` (default 100) → `400`
- Per-message content chars: `max_message_content_chars` (default 100,000) → `400`
- Total content chars: `max_total_message_content_chars` (default 500,000) → `400`

## Error Codes

| Code | HTTP | Meaning |
|------|------|---------|
| `INVALID_JSON` | `400` | Request body is not valid JSON. |
| `INVALID_MESSAGES` | `400` | `messages` missing or empty. |
| `MODEL_NOT_FOUND` | `404` | Requested model is not registered. |
| `STREAMING_NOT_IMPLEMENTED` | `501` | `"stream": true` is not yet supported. |
| `INFERENCE_CONCURRENCY_LIMIT` | `429` | Concurrency limit reached. |
| `MODEL_UNAVAILABLE` | `503` | No failover route configured for the model. |
| `INFERENCE_FAILED` | `503` | All failover providers exhausted. |
| `INTERNAL_SERVER_ERROR` | `500` | Unexpected error (details logged server-side). |
